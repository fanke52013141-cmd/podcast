# 第五步：改文案

前四步做完，声音已经很像本人了，可有些句子一听还是 AI。这时候该查的，往往是稿子。

改稿放在克隆后面，是因为很多毛病要配出来才听得见：眼睛可以往回扫，耳朵只能听一遍。

## 什么算人话

三条，缺一条都不算：

1. **念出来不拗口**：配音模型念得顺，不抢气、不变调。
2. **听一遍就能懂**：不靠回看，不靠字幕。
3. **听得出是一个具体的人在说话**：有这个人的接句方式、口头禅和态度，不是"标准答案"。

## 怎么改：口述、整理、配音、听、改

开口推荐的写稿方式，是作者这几期一直在用的做法：

1. 作者对着 AI 口述一遍想讲的内容（语音输入就行）。
2. AI 整理成稿，按下面的规矩写。
3. 配出来，一句一句地听。
4. 哪句一听就是 AI，就改哪句，只重配改过的句子。

口述的版本太散，到处是"呃""然后"；AI 整理出来的又太干净，干净得不像一个人。人话在这两头的中间：**学作者接句子的方式，口头禅挑着留，填充词不留**。

## 整篇的结构：先给地图，再讲细节

句子改得再像人话，整篇没有逻辑，观众照样看不下去。作者看完全片小样以后提的意见，归纳成下面几条，写长一点的讲解稿时先按这个搭骨架，再改句子：

| 规矩 | 怎么做 | 为什么 |
|---|---|---|
| 开头先给整张地图 | 钩子之后，用三十到六十秒讲清楚：这期讲什么、一共几步、每一步解决什么问题、看完能得到什么 | 观众一开始不知道整件事在讲什么，就没有理由往下看。地图也是后面进度条的来源 |
| 先总后分 | 讲一组东西之前，先一句话把全貌报出来（"这一步管三件事：底噪、环境、回声"；"我总结了六招：……"），再一个一个展开 | 听的人知道一共有几样、现在讲到第几样，就不会迷路 |
| 用问题开头，用"为什么"带路 | 每一步、每一个要点，先抛一个观众心里会冒出来的问题（"录个音，能有什么讲究呢？""为什么要藏起名字？"），再回答 | 自问自答能一步一步把人带进去；讲清楚"为什么要这么做"，比只说"怎么做"更有用，也更难被别的教程替代 |
| 每一段结尾留一个钩子 | 一步讲完，先抛出下一步要解决的问题（"录音干净了，是不是就够了呢？还不够……"） | 让人带着问题进入下一段，而不是在段落之间划走 |
| 埋一两个悬念，后面揭晓 | 例如开头说"有一步大多数教程直接跳过"，到那一步再点破；让观众先猜，下一段再给答案 | 留着没回答的问题，是让人继续看下去最便宜的办法 |
| 请观众参与，但不要多 | 全片两三处：猜一猜、跟着盲听一下、数一数；结尾问"最头疼的是哪一步"引导评论 | 参与感能提高完播和互动；问多了像在拖时间 |
| 不堆数字 | 一段最多一个数字，而且要好记（"五分钟""四遍里一两遍能用"）；实验细节和分数放进说明文档，不放进旁白 | 耳朵记不住一串数字，数字一多，重点反而被淹掉 |
| 每个要点配一个真实的例子或一段试听 | 改前改后的句子、当时盲听的候选、自己踩过的坑 | "具体的人"靠具体的经历撑起来；只讲道理像标准答案 |
| 全片控制长度 | 讲解类以十三到十四分钟为上限；超了先砍"分类、背景、实验过程"，保留"为什么"和"怎么做" | 冗长是完播率最大的敌人 |
| 用弹幕把自问自答说出来 | 全片三四处，把最可能冒出来的疑问写成一条"弹幕"：画面上先飘过这个问题，旁白再接"好像有人在问……""我看到弹幕里有人在问……"，然后回答。挑的是观众真会问的（"录一段不就够了吗""降噪到底要不要开"），回答里只说自己做过、确定的事 | 同样是自问自答，借弹幕的嘴问出来，更像在和观众对话，也给画面一个动的理由。三四处就够，多了像在演戏 |
| 燃点上放一点氛围弹幕 | 猜一猜、盲听揭晓、关子解开、改前改后对比、点赞提醒这些地方，飘过几条短弹幕（"猜聊天的吧""原来是这一步""已赞"）。要观众数成语、数次数的地方不放，免得剧透 | 让画面有"很多人一起在看"的热闹感，把平的地方挑起来 |

## 规矩和原因

| 规矩 | 原因和依据 |
|---|---|
| 两个标点之间不超过 22 个字，长句短句穿插 | 一口气念不完，模型会抢气、变调；全是短句又像念口号。真人写的中文，句子平均长度和 AI 差不多，差别在于长短变化更大（朱君辉等，2023） |
| 句子说完整：主语、量词、连接词不省，少拿单字当动词 | AI 写口播稿为了紧凑会省成分，看着简洁，念出来像电报。实例见下面"真实的改稿" |
| 多用双字词：「测到」写成「测试到」，「需」写成「需要」，「已」写成「已经」，「均」写成「都」。大约七八成换成双字，故意留几个单字 | 口语的节奏是两个字一拍，汉语韵律研究里最基本的「标准韵律词」就是两个音节（冯胜利，1997）。AI 写稿爱用书面的单字词，看着紧凑，配出来一个字一顿，像念公文。可要是全换成双字，又整齐得像机器，所以要留一点随机。这条是作者自己总结的，别的去 AI 味教程里没见过 |
| 语气词每千字 3 到 5 个，放在问句和反应句的句尾 | 真人用语气词的频率差不多是 AI 的五倍（朱君辉等，2023）。放多了拖沓，一段话一两个就够 |
| "呃""嗯"这类填充词不写进稿子 | 听众会觉得讲的人没准备好 |
| 口头禅：先量作者平时的频率，稿子里只留一小部分 | 口头禅最像本人，也最容易用过头。实例：作者口述时"然后/的话/就是"每千字约 40 次，定稿里约 6 次 |
| 成语、俗语、歇后语放在一段话的结论上，一段最多一处，全片七到十处 | 一句熟语比一长串解释好记；用多了像背词典。出处拿不准就只说"古人说" |
| 方言味：放一两个方言词，或者用带口音的讲法录参考 | 带一点乡音的普通话最像真人。方言词要在屏幕上写出意思 |
| 语速有快有慢：重点慢一点，补充快一点，前后差 5% 左右 | 模型自己忽快忽慢最像 AI；完全匀速也像 AI |
| "这是克隆的声音"全片只说一次 | 该说明的要说明（平台的 AI 生成内容声明和简介里写清楚），可一遍遍提醒会把注意力从内容上拉走 |
| 不用"有两个""只有一个"这类总结框架，不用"在……的今天""随着……的发展""日益" | 之前实测：AI 初稿里这类框架每千字 2.52 次，真人最多 0.43 次 |
| 不用"不是……而是……"句式 | AI 稿的高频写法 |
| 不说"最后""总之"（结尾段除外） | 观众听到会以为要结束了，开始划走 |

写完跑：

```bash
python tools/lint_script.py script.txt --idioms idioms.txt
```

它会列出：一口气太长、AI 稿高频写法、书面单字（已、需、仅、均、若、则……，应该是 0 处）、单字动词占多少（建议双字占七到八成五）、每段句长是不是太整齐（变异系数低于 0.3）、语气词和口头禅每千字几次、一段里成语俗语是不是超过一处、"这是克隆的声音"说了几次，并估算时长。

## 真实的改稿（作者前几期的记录）

这些例子都来自真实的旧稿和改稿记录，可以拿来给用户看"改成什么样"。

**补全省略**（《卡字》v4，124 句被改，汉字从 3837 增加到 4300，多 12.1%，念出来反而更顺）：

| 改前 | 改后 |
|---|---|
| 大脑会想，手会写代码，画面它都做得出来。 | 大脑负责构思，双手负责写代码，什么画面它都做得出来。 |
| 但它没有耳朵，听不到旁白念到了哪。 | 但它没有耳朵，听不见旁白念到了哪里。 |
| 每句配四遍再挑 | 每句话配了四遍以后，再进行挑选 |
| 不装卡字，两个模型，十个关键词只卡上一个。 | 不装卡字，两个模型，十个关键词只卡上了一个。 |
| 第四步，画面。时间有了，该画些什么呢？ | 第四步，画面。时间已经有了，那该画些什么呢？ |

**换成双字**（这一组是示意，不是旧稿记录）：

| 单字版（AI 常这么写） | 双字版 |
|---|---|
| 我测了三个模型，均可直接使用，仅需十秒参考即可。 | 我测试了三个模型，都可以直接用，只需要十秒的参考就行。 |
| 若参考不干净，则需重录。 | 如果参考不干净，就需要重新录。 |
| 该模型已支持中文。 | 这个模型已经支持中文了。 |

第一句的双字版里，「直接用」的「用」故意留了单字：每个字都换成双字，读起来反而不像人。

**补语气词**（《AI 做视频工作流》：v2 的 AI 初稿语气词为 0，v4 在开头补了三个）：

> 关注我频道的朋友可能已经发现了**吧**，我最近很多视频**啊**，其实都是用 AI 做的。……到了这条视频**呢**，我干脆连自己的声音都克隆了。

**收口头禅**（同一期）：旁白 v1 有 14 个"就是"（"然后/的话/就是"每千字 12.9 次），v2 删到只剩 2 个（4.2 次），之后照作者的口述整理，定稿 v7 是 6.0 次。作者口述消息里是 39.7 次。

**补成语**（《卡字》v3 专门补了一轮）：例如"是骡子是马，咱们拉出来遛遛"引出实测；背景大字用"差之毫厘"而不是一个"估"字。

## 先配后改的时候，怎么判断"一听就是 AI"

配出来逐句听，下面这些一出现就改：

- 一句话里两个以上的并列短语，节奏一模一样。
- 句尾全是降调的陈述句，连着三句没有问句或反应句。
- 单字动词（"测""估""跑"）念出来像别的字。
- 一句话里塞了两个要观众记住的东西。
- 模型在逗号处一口气念过去，或者在不该停的地方停了很久（这是稿子太长，先改稿，再考虑后期）。
