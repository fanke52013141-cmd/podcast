## 1. TTS 多引擎：本地 + API 双轨

### 1.1 目标架构

现有 `TTS_ENGINE` 开关从 2 引擎扩到 **4 引擎**，统一走既有 `synthesize(script_dict, out_wav)` 契约（逐轮合成 → 拼接 → 轮级缓存）：

```
tts_service/
├─ server.py            # 引擎路由（TTS_ENGINE=soulx|indextts|minimax|doubao）
├─ soulx_wrapper.py     # 本地·默认（对话感最好，实测 A/B 结论）
├─ indextts_wrapper.py  # 本地·ComfyUI（逐轮重做/语速控制）
├─ minimax_engine.py    # 新增·API（T2A v2 同步/异步双通道）
└─ doubao_engine.py     # 新增·API（火山 seed-audio-1.0）
```

### 1.2 MiniMax 引擎（协议从 free-creation `audio.ts` 实战代码逐条核对）

| 通道 | 端点 | 用途 |
|---|---|---|
| 同步 | `POST {base}/v1/t2a_v2`，`Authorization: Bearer`，响应 `data.audio` = **hex 编码**音频 | 单轮短文本（我们逐轮合成天然适配） |
| 异步 | `POST {base}/v1/t2a_async_v2` → 轮询 `/v1/query/t2a_async_query_v2?task_id=` → `/v1/files/retrieve?file_id=` 取下载地址 | 长轮次（>几千字）兜底 |

**必须照抄的实战坑**（free-creation 注释里都是真金白银踩出来的）：
1. `voice_setting.voice_id` **必填**，缺失直接被拒（`invalid params, voice id wrong`）→ 引擎默认回落音色
2. 异步通道下载产物**可能是 TAR 归档**（content-type `application/x-tar`），必须解包取音频成员，否则落盘的是永远播不响的假 mp3
3. 错误判定统一看 `base_resp.status_code != 0`；HTML 错误页也要归一化
4. 提交回执里的 `file_id` 不能立刻检索（文件要等任务成功才存在），必须先轮询到 `success`

### 1.3 豆包引擎（火山引擎语音合成 1.0）

- 端点：`POST {base}/api/v3/tts/create`，头 `X-Api-Key` + `X-Api-Request-Id`（UUID）
- 模型：`seed-audio-1.0`；**零样本克隆**：`references: [{audio_data: base64}]` 直接吃参考音——正好把音色库现有 5-10s 参考音转 base64 喂进去，无需预登记
- `text_prompt` 前缀拼接参考音提示（free-creation 的 `volcReferencePromptPrefix` 逻辑）；`speaker` 可选传 voice_id
- 响应同步：`{code, audio: base64, subtitle}`，code≠0 报错
- 同步返回**字幕**（`enable_subtitle: true`）→ 白送的对齐数据，可喂给后期时间轴

### 1.4 音色库与设置页改造

- `voice_lib/manifest.json` 每个音色增加 `engines` 字段：
  ```json
  {"id": "v01", "engines": {
      "soulx":  {"prompt_audio": "voice_lib/audio/v01.wav"},
      "indextts": {"prompt_audio": "voice_lib/audio/v01.wav"},
      "minimax": {"voice_id": "canvas-voice-xxxx"},
      "doubao":  {"reference": "voice_lib/audio/v01.wav"}}}
  ```
- 设置页新增「API 合成」分区：MiniMax Key + base_url（默认 `https://api.minimaxi.com`，支持网关）、豆包 Key；各带「测试连接」（一次 1 句话合成探活）；Key 沿用 `.env` 掩码存储
- 工作台「引擎」下拉同步扩展：本地 SoulX / 本地 IndexTTS / MiniMax / 豆包
- 计费提示：API 引擎按字符计费（MiniMax speech-02 系约 ¥xx/万字符），工作台成本估算行联动引擎

### 1.5 验收
- 同一 10 轮 token 稿，4 引擎各出一版 → `/static/compare.html` 扩展成 4+1 对照
- 引擎不可用（Key 缺失/欠费）时任务失败信息可行动（沿用 base_resp 归一化）

## 2. 音色库第三方兼容 + 音色设计工厂（MiniMax 为主）

> 审查补全（2026-11-18 二审）：初版方案只写了"设计→入库"，漏了音色库对第三方音色的
> **展示/试听/绑定/管理**四件事。本节为补全版。

### 2.0 音色库第三方兼容（新增，初版遗漏）

| 缺口 | 补全设计 |
|---|---|
| **试听播放路径** | 现有卡片"▶ 试听"播 `/api/voices/{id}/audio`（本地 wav）。MiniMax 设计音色**没有本地参考音**——入库时把 `trial_audio` 解码存为 `voice_lib/audio/{id}_trial.mp3`，试听接口优先播它；详情可加"重新生成试听"（调 t2a_v2 用该 voice_id 现合成一句） |
| **音色↔引擎亲和** | 音色设为主持/搭档后，若当前 TTS 引擎不在该音色 `engines` 支持列表里（如 MiniMax 音色 × SoulX 引擎），**绑定即失效**。规则：① 卡片"设为主持/搭档"时按音色首选引擎自动带出引擎建议；② 工作台引擎下拉只显示当前双主播音色都支持的引擎（不可选的置灰并注明原因）；③ 后端 create_job 校验 voice×engine 兼容性，不兼容直接 400 报可行动错误 |
| **来源标注** | manifest `source` 枚举扩展：`self_recorded / public / generated` → 增加 `minimax_designed`（AI 设计）、`minimax_cloned`（复刻）。卡片小标显示"MiniMax 设计/MiniMax 复刻"，并显示 voice_id 尾号 |
| **复刻为一等公民** | 音色库"上传参考音"弹窗增加开关"同时复刻到 MiniMax"（默认关）：勾选则走 `/v1/files/upload` → `/v1/voice_clone` 链路，成功后该音色同时获得 `engines.minimax.voice_id`；失败不阻断本地上传 |
| **豆包零成本兼容** | 豆包走 references 零样本克隆，**任何有本地参考音的音色天然可用**（含官方样音/自录音）；卡片引擎徽章按 `engines` 字段动态显示：本地● MiniMax● 豆包● |
| **删除策略** | 删除 MiniMax 音色只清本地 manifest 与 trial 文件，**不调远端删除**（MiniMax 无公开删除接口）；卡片删除确认文案注明"远端 voice_id 保留，不再计费" |

### 2.1 协议（free-creation `voice.ts` 已核对）

- `POST {base}/v1/voice_design`，Bearer 鉴权
- 请求：`{prompt: 音色文字描述, preview_text: 试听文本, voice_id?: 自定义ID, aigc_watermark}`
- 响应：`{voice_id, trial_audio}` —— **trial_audio 是 hex 编码 mp3**，解码即试听
- voice_id 命名规则：8-256 位、字母开头、仅 `[a-zA-Z0-9-_]`、结尾不能是 `-`/`_`（前端即时校验）
- 复刻链路：`POST /v1/files/upload`(multipart, purpose=voice_clone) → `POST /v1/voice_clone`（file_id + voice_id + model + 降噪/归一开关 + 可选 clone_prompt）
- 关键坑：回执 `base_resp.status_code=0` 但 `input_sensitive=true` 时**音色并未登记**，必须拦截报"换干净录音"；克隆超时时远端可能已登记，提示先查再重试防重复创建

### 2.2 产品流程（音色库页）

```
[AI 设计新音色] → 弹窗：文字描述 + 试听文本 + （可选）自定义voice_id
  → voice_design → 播放 trial_audio → 满意？→ 入库（engines.minimax.voice_id + trial mp3 落盘）
                                    → 不满意？→ 改描述重试（每次都产生新试听，不入库）
入库后：卡片显示"MiniMax 设计"徽章 → 可设为主持/搭档（带引擎亲和校验）→ 工作台选 MiniMax 引擎全链路使用
```

### 2.3 验收（用户明确要求）

**用 5 条不同文字描述设计 5 个音色**，各出一条试听音频，放到独立试听页（复用 compare.html 模式）供用户试听评分，例如：
1. 温柔知性女声，语速偏慢，适合深夜电台
2. 阳光活力男声，年轻，语速快，适合资讯快节奏节目
3. 低沉磁性男声，中年，沉稳，适合商业访谈
4. 清脆伶俐女声，伶牙俐齿，适合漫才吐槽担当
5. 温和学者男声，中老年，娓娓道来，适合知识科普

⚠️ **硬前置：需要用户提供 MiniMax API Key**（voice_design 按次计费，5 条试听成本可忽略但必须有 Key）。
